# 机构干预日志

通过 CLI 对话收集机构观察，最终写入 `tracking/log/institution/YYYYMMDD.md`。使用 `20260922.md` 的标题、说明和三列表格格式。

## 对话与写入

1. 确定日期并读取对应日志；新日期准备新文件。日期不明、多个日期混杂或与现有文件冲突时先提问。
2. 在对话中逐条收集活动、表现和提示／支持。用户可以随时要求**追加、修改、删除**整行或某个字段；目标不唯一时引用候选内容，请用户指明。根据内容逐条询问缺失的关键细节，不必为每个空白字段提问。
3. 先在对话中维护变更草稿，不写文件。将推测与观察分开；含义不清、互相矛盾或会改变记录结论的信息，直接提问。用户无法确认的内容从草稿中省略；未提供的普通细节可用“—”或“未记录”表示。
4. 每轮补充后可简要复述已收集内容并询问是否继续。用户表示没有更多内容时，展示将写入的完整新日志或现有日志的具体变更，询问是否结束并写入。只有用户明确确认结束或直接要求保存，才一次性新建或更新文件；明确的“保存／写入／就这样”已是确认，无需重复询问。沉默不代表确认。
5. 写入后核对日期、表格结构和本次增删改内容，告知用户文件路径与实际变更。

追加时将同一活动的补充合并到对应行；不同情境或不同尝试可分行。修改时只改指定内容，删除时只删指定行或片段，保留其他已有记录。新旧信息冲突时在写入前问清采用哪一条。

## 日志格式

```markdown
# 机构干预日志：YYYY-MM-DD

根据本次交流整理。表格中的“—”表示未提及，不代表无需支持。

| 活动/情境 | 观察到的表现 | 提示/支持 |
| --- | --- | --- |
| 活动名称 | 具体行为、持续时间或结果。 | 成人提示、陪同或环境支持；未提及时写“—”。 |
```

整理已有文件时保留其说明文字，表格维持“活动/情境｜观察到的表现｜提示/支持”三列。记录中不设“待确认”部分，也不写尚未核实的推测。“表现”写可观察动作或用户明确给出的描述；持续时间、次数、独立完成情况和支持程度仅在用户提供时写入。避免用概括性评价代替具体情境。

## 交付

只将已确认的内容写入日志；不据此给出诊断或擅自制定治疗方案。
