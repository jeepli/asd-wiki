# 小红书图文提取

目标是把一篇公开可访问的小红书笔记整理成 `raw/xhs/<日期>_<标题>/` 目录，目录内包含原图、`metadata.json` 和 `README.md`。用户要求提取正文时，直接把图片文字合并到 `README.md`，不另建正文文件。只处理公开页面，不依赖登录态、Cookie、验证码或第三方付费 API。

## 标准流程

1. 先保留用户提供的原始链接，并用移动端 User-Agent 跟随短链跳转。优先使用随附脚本：

   ```bash
   python3 .agents/skills/xiaohongshu-note-extract/scripts/extract_xhs_note.py \
     "<链接>"
   ```

   默认输出根目录是项目根目录下的 `raw/xhs`。需要更换根目录时使用 `--output-root <目录>`；`--output-dir` 仍作为兼容别名，但它表示根目录，不是最终帖子目录。

2. 脚本从最终公开详情页解析 `note_id`、`xsec_token`、标题、描述、作者和图片 URL，并下载图片。详情页通常是：

   `https://www.xiaohongshu.com/discovery/item/<note_id>?xsec_token=...&xsec_source=app_share`

   使用移动端 User-Agent 是关键；桌面端同一链接可能重定向到登录页。

3. 脚本使用 `noteData.time` 作为日期，缺失时依次回退到 `lastUpdateTime` 和当前日期；默认按 `Asia/Shanghai` 转换。目录名格式为 `YYYY-MM-DD_<安全化后的标题>`，例如 `2026-09-16_如果你觉得自己不太会干预孩子，就死磕这6件事`。同日期同标题的不同帖子会追加 `_<note_id>`，禁止覆盖已有帖子。

4. 检查输出是否包含标题、作者、标签、图片数量和所有图片文件。图片 URL 要保持页面中的顺序，并统一改用 HTTPS 下载。

5. “正文”分为页面字段和图片文字两层交付：

   - 页面元数据中的标题、描述和话题标签写入 `metadata.json` 与 `README.md`。
   - 用户说“提取正文”“提取内容”或要求完整文字时，必须处理已下载图片中的文字：优先使用可用的本地 OCR；OCR 不可用、结果不完整或版式复杂时，逐张视觉核对并人工整理。直接合并到 `README.md` 的“描述/话题”字段下，保留标题、段落、编号和原文顺序；跨页句子只在确有连续证据时合并。
   - 正文按连续内容整理，不需要在每一段标注对应图片来源；只需在识别说明中概括覆盖的图片范围和识别方式。
   - 不得根据标题、上下文或常识补写图片中看不清的字。无法确认的内容使用 `【待核对】` 或 `【疑似：…】` 标记，并在 README 的识别说明中注明；不要把图片文字未经核对地写回 `metadata.json` 的页面描述字段。

6. 最终交付原始短链、实际输出目录或压缩包，并说明哪些文字来自页面字段、哪些文字来自图片识别或人工整理。

## 访问边界

- 只跟随用户给出的链接和一次明确的公开详情页路径；不要批量枚举笔记、绕过验证码、注入 Cookie 或尝试获取私密内容。
- 页面要求登录、返回风控页或没有公开 SSR 数据时，停止抓取并说明需要用户提供可访问页面或手动下载的图片。
- 不把 Cookie、浏览器会话、手机号、验证码或账号信息写入输出文件。
- 小红书笔记可能包含医疗、教育或育儿建议。提取时保持原作者表述与事实整理的边界，不把内容包装成专业诊断或建议。

## README 交付格式

当用户要求正文或图片文字时，正文与元数据合并写入 `README.md`，默认采用仓库现有的连续描述格式：

```markdown
# 小红书笔记提取

- 来源：……
- 日期：……
- 目录：……
- 标题：……
- 作者：……
- 描述/话题：1.……

正文段落……

2.……

正文段落……

- 图片数量：……
- 图片文字：已按图片顺序核对，识别方式为……，覆盖……

## 图片

1. [01.jpg](./01.jpg)
```

正文采用连续的编号或自然段，不拆成按图片编号的小节，也不在每一段重复图片来源；图片没有可读文字时在识别说明中注明。医疗、教育或育儿相关内容按原作者表述整理，不改写成专业建议。

## 完成标准

只有在以下条件都满足时才报告完成：`raw/xhs/<日期>_<标题>/` 或用户指定根目录下的实际帖子目录存在；`metadata.json` 可读；README 中有来源、日期、标题、作者和标签；图片数量与元数据一致；每张图片都能被打开；若用户要求图片文字，README 已包含连续正文、识别方式、覆盖范围和不确定处说明。
